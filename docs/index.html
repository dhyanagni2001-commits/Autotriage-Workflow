AutoTriage

A support-ticket triage agent that knows when not to act. It combines a fine-tuned retriever, a DistilBERT intent classifier and LangGraph routing. Safety guardrails decide whether to auto-resolve, draft-and-hold, or escalate.

Try the router See real agent runs GitHub

How it works

Each stage is evaluated on its own. The models' outputs feed into routing rules, and an auditable guardrail runs before any automated action.

1 · RetrieveFine-tuned MiniLM + FAISS over a 27-article KB
→
2 · ClassifyDistilBERT, 27 intents → 6 routing categories
→
3 · DecideRisk guardrail, confidence gate, refund limit
→
4 · Act + auditSimulated refund/CRM, or escalate, with full trace

    These are outputs from the trained models on 80 hand-written tickets, with each ticket's expected action labeled by a person. The held-out set was written and scored before the guardrail existed and was not used for tuning. Misrouted tickets have a red border.

    Results

    Near-perfect accuracy in-distribution didn't carry over to hand-written tickets. The end-to-end eval surfaced the gap, and two targeted changes closed the unsafe part of it.

    Bitext is templated, so the in-distribution scores are near ceiling. The hand-written sets are the more honest signal, but they are small: they show failure modes, not production error rates. Refund and CRM actions are simulated.

    Built with PyTorch, Sentence-Transformers, FAISS, Hugging Face Transformers, scikit-learn and LangGraph. Numbers are reproducible from the repo; raw outputs are in results/.
